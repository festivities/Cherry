# Cherry — Device testing notes (TESTING.md)

What the main agent needs to write a `cherry-tester` brief, and what a tester needs on the device: tap rules, per-screen routes and coordinates, known traps. Moved verbatim out of [AGENTS.md](AGENTS.md) "Workflow" on 2026-11-10 so that sessions which do no device testing do not load it. The rules about who tests and how the chain runs stay in AGENTS "Workflow" (Device testing). Read this file before writing a tester brief; name the bullets a tester must read in the brief.

Coordinates are for the named AVD at the named date and are starting points only: testers re-check every position by screenshot. Serials follow emulator start order, and **a third AVD (`Raspberry`) belongs to the Raspberry session** (AGENTS "Lab"): on 2026-11-10 it was running alone as `emulator-5554`, the serial the tap permissions in `.claude/settings.json` allow. Check `adb -s <serial> emu avd name` before every test and never send input to that AVD.

- **Tester practicalities (learned 2026-10-11):**
  - Taps are allowed by the project rules in `.claude/settings.json` (`Bash(adb -s emulator-5554 shell input:*)`, added by the user; the auto-mode classifier refuses both the taps and agent-side settings edits, again on 2026-10-22. The user added `Bash(adb -s emulator-5556 shell input:*)` for the second emulator on 2026-10-22). Briefs must tell testers to use exactly `adb -s <serial> shell input tap|swipe …`. If a tap is refused, the tester stops; never route it through another tool, and never do the tap yourself.
  - **Serials follow start order, not the AVD:** the first emulator started is `emulator-5554`, the second `emulator-5556`. Every brief names the AVD and the serial checked with `adb -s <serial> emu avd name` right before the test; the two AVDs have different screen sizes, so coordinates never carry over.
  - A new game day (06:00 JST) opens the daily login calendar at app start, which blocks a tester. Say in the brief whether it may claim it (lab account 1001: yes) or should stop.
  - Emulator: swipes that start low on the screen trigger Android's home gesture (the app goes to the background); scroll with mid-screen swipes (y 900–1800, ≤700 px). android-mcp `ConnectDevice` fails on the emulator; testers use `adb exec-out screencap` + `input`.
  - Menu labels are Cherry's own (`data/menu.json`; link types and order in `internal/web/http.go` `homeLinks`): the pet shop is "Minipet Shop", the gacha entry is "Gacha Shop" (page 1). Every kept row is answered since the 2026-10-28 cleanup, so a mis-tap opens a neighbour instead of a 404 — testers check the label under the icon and the log after each tap. The plain "Square" item sits between "Settings" and "Postbox" (emulator: MENU, one 400 px mid-screen swipe, then wait for the grid to settle before tapping). Square fishing: after GO, tap open ground above the bottom panel to walk down (the café table sits under that panel at arrival), tap the right chair of the top table (Square now shows COLLECT top right and BAIT/ROD bottom left; the fish shop bubble is ~10 tiles east of the café), START, then one HIT tap about 1 s after the bite (~4 s after START; separate adb calls, no screenshots in between). Leaving while fishing asks "Do you want to stop fishing?" (OK).
  - Testers do not count duplicate refunds or login bonuses; verify balances against `ledger.jsonl` before calling a mismatch.
  - MENU grid: after a swipe the grid keeps drifting for several seconds; wait until two consecutive screenshots match before tapping. A mis-tapped neighbour cell (e.g. the shop sublist) shows "Network Error."; testers may dismiss that one popup with OK and must count it.
