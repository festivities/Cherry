## Mission

Reconstruct a Go server emulator ("Cherry") for LINE PLAY (jp.naver.lineplay.android), LINE Corporation's avatar social game (2012–2024), so the real, unmodified Android client is fully playable. The lobby bootstrap (M0–M4) is long done; the goal is full game functionality. A Windows client port comes later.

## Tooling rules

- Prefer `ida-mcp` (open `%TEMP%\opencode\cherry\lib\arm64-v8a\libgame.so.i64`, read-only; enumerate sessions — IDA session ids are ephemeral — and close without saving). `jadx-mcp` for DEX/Java (Androguard fallback). Glass where IDA is unavailable; its ARM32 caller output proved unreliable (use a checked Capstone scan). Route strings: `%TEMP%\opencode\cherry\tools\http-static` (`bss_string_globals` dump — the `.bss` URL slots are empty in the IDB) and `%TEMP%\opencode\cherry\economy-20261006\routes_all.txt`.
- **jsoncpp shapes matter:** `asInt`/`asString`/`asBool` on the wrong type misbehave, and an object where the client indexes an array has crashed the client (GLThread SIGSEGV). Verify every reply shape against the native parser before serving it. For LPNP protobufs verify required fields (`IsInitialized` masks): one invalid entry makes `roomclient_dispatch` drop the whole frame.
- Short, bounded commands (about 10–30 s for status probes; `timeout` on every adb call); no unbounded loops or long tshark retries. Use the dedicated read/edit/search tools.
- **Git Bash rewrites absolute device paths** (`/data/local/tmp/x` becomes `C:/Program Files/Git/data/local/tmp/x`): `export MSYS_NO_PATHCONV=1` before `adb push`/`adb shell` with device paths, or use PowerShell. In PowerShell use PowerShell syntax only. When generating docs or code with Python, beware `\r`/`\n` escapes inside Windows paths; prefer the file-write tool for long text.
- Keep Go sources gofmt-clean with LF endings (workers have introduced CRLF before).
- Android UI: read the current `wm size`; old tap coordinates are historical. Native Cocos screens need a fresh screenshot after each tap (MCP Wait/WaitForElement time out). On the phone, emulator-derived coordinates miss. Menu items: tap the icon cell about 80–100 px above the label.
- The model can view images returned by tools; if a tool fails, record the tool error instead of inferring the UI.
- Static route attributions can be wrong at runtime (e.g. the pet shop buys through `purchase/interior/buy`, not `purchase/pet/buy`). Cherry's log has no request bodies; shop/recycle rejections log their (credential-free) body as `cherry: shop reject`. Check the live log before trusting a static guess.
- **Client crash triage:** `adb -s <dev> logcat -d -b crash` gives the native backtrace (the emulator's `/data/tombstones` may hold only older crashes). A backtrace names the parser, not the route: correlate the crash time with the last requests in the Cherry log (`summarize-log.py`) before changing a reply — the gacha crash named `ResGachaCategroy` but the trigger was `home/sublist/gacha`, not `catg/all/0`.
- Raw HTTP/session/protobuf/pcap data is credential-bearing; keep it in `%TEMP%`. `formatHeaders` redacts Cookie/Auth/token values in Cherry's log.

## Architecture (static recon; verify before coding)

### Client stack
- cocos2d-x 2.2.5, custom NHN layers (`arts`/`ArtsPf`), game ns `Na*`, net layer `XSystem`/`XInNetwork`. No Lua/JS/WebSocket.
- `libgame.so`: 119,419 functions, symbols NOT stripped, not obfuscated.
- JNI bridge: `com.nhnarts.message.PfQueueEvent` (~90 native methods, list in temp `tools\native_methods.txt`).
- DEX class `android.line.s.Service` loads protection/browser libraries via runtime-decrypted names. Glass's APK lift failed on an invalid class-name string; that tool failure alone does not establish why it failed or deliberate obfuscation as its cause.

### Protocol stacks (static-confirmed 2026-09-21; full reports in temp `cherry\tools\{airarmor,http,lpn}-static\REPORT.md`, main-agent spot-verified)
1. **Native HTTP/JSON** (libcurl static, jsoncpp): base `https://<host>/v4/`. fapi.play.naver.jp (game API), fapi-diary, event, face, gws, terms.line.me, notice2.line.me; CDNs play-static.line-scdn.net / play-static.line-apps.com, obs.line-{apps,scdn}.com. `tx.lbg.play.naver.jp` is an HTTPS API base (billing), NOT an LPN socket. 326 URL builders on `NaDataInvokerProtocol` (list: temp `cherry\invoker_short.txt` if present; addresses in http-static\ADDRESSES.txt).
2. **Session XTCP/JSON** — `session.play.naver.jp:10123` (XPN string, verified at 0x2f818b8). Frame `LO`: `BE32(len+16) "LO" 0x10 flag BE32(payloadLen) BE64(txnId) payload` (payload = JSON control: sendInit sessionId/sessionKey/country/os/lpVer; configure → pingSeconds/noopSeconds). Built by `LPNConnector::Send(raw)` 0x2a186a4 (callers: NaSessionManager::sendInit 0x1b30964, OnPushReqest).
3. **Game gateway LPN** — gws.play.naver.jp, **default port 10000** (`LPN::GetGatewayServerPort` 0x2a17a20 = `return 10000`; only observed caller in `NaSingletonManager::Initialize` at 0x19209cc; internal CreateOption only; no server-exposed override). `/v4/setInitConf.sessionServerInfo` + `SessionInvoker::parseConfigure` @0x1b3b67c configure :10123 only (static-confirmed). Frame (both dirs): `BE32(len = ALL bytes after the length field) | tag | type | BE64(sessionId) | payload`; tag 'G'=game data, 'D','F','L','M','H' variants; type=(agenttype-1)<<3|subtype. Payload = **BE16(msgid)** || protobuf (msgid BIG-endian — corrects early recon; ids namespace-scoped; tables in lpn-static\dispatch_tables.tsv: CIRCLE 55, MONOPOLY 38, LPNP 36, SQUARE 133, GARDEN 82, TLUP 6 entries; outbound GetIndex == inbound dispatch index).
- **Mode 3 (AES-128-CFB128)**: BE32(len) stays PLAINTEXT; bytes from offset 4 encrypted: AES("LP" || BE64(sessionId) || BE16(msgid) || protobuf); EVP re-init per frame (CFB reset), same key+IV both directions; mode 4 = plaintext. Handshake: server 15-byte banner (`00 00 00 08 00 00 …`) → client 11-byte reply `00 00 00 04 00 00 01 0A 35 ED 6A` (order verified from STRB trace 0x2a0c8f0–0x2a0c918; **live vector captured 2026-09-22: `000000040000010a35ed6a`; banner works**) → mode 4 → server `HI` frame `BE32(14) "HI" BE32(keyIndex) BE64(threshold)` → client picks from its 100-entry key table → mode 3; `HO` = stay mode 4. Ping `BE32(2)|'M'|sub` (81='Q', 83='S'; inbound 'M'+85='U' → disconnect); keepalive timeout default 5000ms — the client drops the link after ~5 s with no inbound frame, so Cherry echoes every client `M` ping except 'U'.

### Auth (static-confirmed 2026-09-21; runtime corrections 2026-09-22)
- LINE SDK v3 embedded (channel-apis.line.naver.jp); channel ID 1350636423. NOT emulating LINE OAuth — local guest route: UI selector **`LD_GUEST`** (string @0x2f8b2e0; NaLoginLayer::MakeLoginButton 0x1cfe130, SNS list-driven layouts SetSnsLoginUITagList 0x1cfe4d0). Guest uniqueCode = device UUID via LoginAdapter.InfoDeviceUUID (saved pref `uuid`, else name-based UUID from ANDROID_ID).
- Guest: POST `https://fapi.play.naver.jp/v4/account/guest/generate` body `{"uniqueCode":"…"}` header `X-LINEPLAY-ACNT = lowercase_md5hex(uniqueCode + "vocky7dkd722i1u8ak84o")` (secret verified @0x2f7d910) → `result.provider` (**"lineplay" on the wire, not "GUEST"**), `result.accessToken`.

## Known client-inherent limits (do not re-investigate without new evidence)

- **Garden position resets** on Profile → Friends → back: room-enter 197377 reloads the map and `InitHero`/`SetAvatarDefaultSpawn` overwrites the hero position; this client has no ordinary-walk position report. User-approved disposition 2026-10-04 (evidence in HISTORY). The user remembers the official game keeping position; production behavior is unverified.
- **Garden walking and chat cannot sync:** the client never builds Garden outbound move/action/chat requests (idx 7/8/9/10/14); visitors are placed and driven by the server (PLAN "Garden").
- **Room Deco is blocked during a Room Party** (client message), so live furniture refresh for party guests is moot.
- **The stock Closet has no shop entry** (its Go-Shop button opens Storage); shops are reached from the home menu only. **No authentic item names exist** in the archives (the string table has UI text only; 2014 `itemName.txt` holds resource names), so `items/{dress,room}/some` names are Cherry-made.
- **In-game WebView pages on sunk hosts cannot load** (self-signed cert, see Auth/TLS): the gacha odds page is unreachable; the gacha detail screen states the odds instead.
- **Many client error paths ignore errorCode** (e.g. Delete Avatar, voucher purchase): custom error text is impossible there; a client-side pre-check is the only way to get native messages.
