## Mission

Reconstruct a Go server emulator ("Cherry") for LINE PLAY (jp.naver.lineplay.android), LINE Corporation's avatar social game (2012–2024), so the real, unmodified Android client is fully playable. The lobby bootstrap (M0–M4) is long done; the goal is full game functionality. A Windows client port comes later.

## Policies (user decisions)

- **R2/D1 layout: ground truth and Cherry-made content stay separate (user, 2026-10-26).** R2 `static/` holds only byte copies of the original device backups (santi, lpbackup) — the uploader refuses anything else there. Everything Cherry makes lives under `cherry/`: the indexes `cherry/manifest/<cat>.json` + `cherry/manifest/packs.json` (moved from `manifest/` on 2026-10-26, verify green; the reader's legacy `manifest/` fallback and `MigrateManifests` are marked `ponytail:` for removal) and future generated files (e.g. generated landscape items under `cherry/item/garden/<id>/`; `packs.json` entries carry `origin` original|cherry). - **No client modifications.** No client patches, no Frida in normal runs (Frida triggers AirArmor [AA-010]), no blanket chmod of app files. - **`.agents/JICAMA.md` is tracked (2026-10-04).** Keep its content unchanged unless the user asks. Its labels (observed / parser-derived / synthetic / modified-client replay) still matter: it is not stock-client or production proof — verify claims against Cherry and the binary first.
- **Operator-editable fabricated content (user, 2026-10-25):** everything Cherry invents because no ground truth exists — crafting recipes, item and material names, gacha rates and pools, prices, sell-back rates, drop tables and weights, fish tables, reward amounts and caps, quest and calendar rewards, deals, seasonal item picks — must live in data that server operators can edit, add to and remove from without touching Go code. ## Workflow (user instructions)

- **Delegation:** native research and implementation go to the Haiku `cherry-worker` subagent (`.claude/agents/cherry-worker.md`) with self-contained prompts. The main agent coordinates, deploys, reads logs and writes docs. Give workers file ownership when several run at once.
- **Reviews are main-agent-only (2026-10-05).** Never delegate a review; delegated work never replaces the main agent's review.
- **Device testing (2026-10-11, supersedes 2026-10-06):** delegated to the Haiku `cherry-tester` subagent (`.claude/agents/cherry-tester.md`). Subagents cannot spawn subagents, so the main agent chains them: `cherry-worker` implements → main agent reviews and deploys → main agent spawns `cherry-tester` with explicit steps (device, taps, expected screens/log lines) → main agent reads its report and the Cherry log and relays results. Testers never edit code/data or restart Cherry. The main agent itself still does not drive device tests; "check the device state" means a read-only look (screenshot, log, file listing). The main agent may relaunch the app (deploy recipe) when a tester finds it stopped.
