## Mission

Reconstruct a Go server emulator ("Cherry") for LINE PLAY (jp.naver.lineplay.android), LINE Corporation's avatar social game (2012–2024), so the real, unmodified Android client is fully playable. The lobby bootstrap (M0–M4) is long done; the goal is full game functionality. A Windows client port comes later.

- **Economy (2026-10-06):** a full in-game economy on the Club Penguin Legacy model — currency is earned only by playing (minigames, quests, daily rewards, occasional staff giveaways) and spent on items. **No real-money/fiat purchases of any kind**: no paid currency, memberships, VIP, season pass, ads; every billing path stays unavailable. Nothing is handed out on day one except the starter kit. Details, phases and amounts: PLAN "Economy".
- **No client modifications.** No client patches, no Frida in normal runs (Frida triggers AirArmor [AA-010]), no blanket chmod of app files. Re-discussed 2026-10-11 (APK changes for WebView trust or rewritten hostnames; a device-side certificate install for in-game WebView pages): neither approved. A re-signed APK trips AirArmor state 6 REPACKAGED (blocking popup), needs reinstall + data restore, and breaks the stock-client mission. Player distribution is deferred (PLAN "Roadmap").
- **`.agents/JICAMA.md` is tracked (2026-10-04).** Keep its content unchanged unless the user asks. Its labels (observed / parser-derived / synthetic / modified-client replay) still matter: it is not stock-client or production proof — verify claims against Cherry and the binary first.
- **Operator-editable fabricated content (user, 2026-10-25):** everything Cherry invents because no ground truth exists — crafting recipes, item and material names, gacha rates and pools, prices, sell-back rates, drop tables and weights, fish tables, reward amounts and caps, quest and calendar rewards, deals, seasonal item picks — must live in data that server operators can edit, add to and remove from without touching Go code. To undo a test's effects, edit the specific records (or copy the current token aliases into the restored file) instead. Recovery path: guest login rebinds by device UUID (handoff 2026-11-02 progress).
- **Resets:** prefer the in-game **Delete Avatar** flow to restart an account. App-data resets / new guests only on explicit user request (done: emulator 2026-10-03, phone 2026-10-07). Back up `accounts.json` (and `social.json`) before any data edit, and stop Cherry before offline store edits.

## Workflow (user instructions)

- **Delegation:** implementation and native research go to the Haiku `cherry-worker` subagent (`.claude/agents/cherry-worker.md`) with self-contained prompts; binary/protocol specs (IDA, jadx, captures) go to the generic `reverse-engineer` subagent with the spec file it must write named in the brief (user's global rule; the specs under `%TEMP%\opencode\cherry\` come from it). - **Reviews are main-agent-only (2026-10-05).** Never delegate a review; delegated work never replaces the main agent's review.
- **Device testing (2026-10-11, supersedes 2026-10-06):** delegated to the Haiku `cherry-tester` subagent (`.claude/agents/cherry-tester.md`). Subagents cannot spawn subagents, so the main agent chains them: `cherry-worker` implements → main agent reviews and deploys → main agent spawns `cherry-tester` with explicit steps (device, taps, expected screens/log lines) → main agent reads its report and the Cherry log and relays results. Testers never edit code/data or restart Cherry. The main agent itself still does not drive device tests; "check the device state" means a read-only look (screenshot, log, file listing). The main agent may relaunch the app (deploy recipe) when a tester finds it stopped.
