## Mission

Reconstruct a Go server emulator ("Cherry") for LINE PLAY (jp.naver.lineplay.android), LINE Corporation's avatar social game (2012–2024), so the real Android client is fully playable. Until Roadmap 8 the lab runs the unmodified client; since 2026-11-09 the user's direction is a minimally patched, endpoint-agnostic client with Discord-only sign-in on a DB-backed, staff-editable Cherry (PLAN Roadmap 8, Policies). The lobby bootstrap (M0–M4) is long done; the goal is full game functionality. A Windows client port comes later.

- **State lives in memory, guarded by two global mutexes.** `store.Accounts` is a `map[token]*Account` (the account's own access token and every alias point at one struct), guarded by `store.AccountsMu` (a `sync.Mutex`, 119 lock sites: economy 85, web 20, store 6, room 4, lpn 2, testutil 2); social data is guarded by `store.SocialMu` (40 lock sites). Handlers hold `*Account` pointers under the lock and mutate fields in place.
- **Every save rewrites a whole file.** `store.SaveAccountsLocked()` (69 call sites) marshals ALL accounts and aliases and writes temp + fsync + rename under the lock; `SaveSocialLocked` (17 call sites), `SaveCirclesLocked` and the Treasure World store do the same for their files. `accounts.json` is 313 KB for three accounts (1001 alone owns 5,818 codes). The cost of one mutation therefore grows with the total data, and that, not the mutex, is the scaling limit.
- **Money is not atomic across files:** `store.FlushLedgerLocked` appends to `ledger.jsonl` after the account save, and a failed append is only logged.
- **Tokens are stored in clear** (`accounts.json` `aliases`, the map keys); aliases are never pruned.
- **Single-player shortcuts that are wrong for a public server:** `store.CurrentAccount` returns `store.LatestAcc` (the newest account) when a request carries no token, and `economy.HandleWelcomeGift` falls back to it too; `store.LabAids` grants (9 sites); the loopback staff tool trusts `adminLoopback` (6 sites); diary photo uploads are accepted without `AV_AUTH` and share one 1 GiB quota (`web/media.go`); `GuestAccountLocked` scans all accounts; `deleted-accounts.jsonl` keeps every deleted account for ever.
- **Configuration is constants:** `:443`, `:80` and `:10123` in `cmd/cherry/main.go`, `:10000` in `lpn/observer.go`, `:53` in `netsvc/dns.go`, `127.0.0.1:8099` in `economy/economy.go`; the data directory is `os.UserCacheDir()` + `Cherry` at 11 call sites in 11 files (`store` ×4, `assets` ×2, `opdata`, `thumbs`, `web/media.go`, `cmd/cherry-assets`, and the `CHERRY_FAKE_NOW` guard in `cmd/cherry/main.go`).
- **Portable already:** game-day time uses `time.FixedZone("JST", …)` (three places), so no tzdata is needed on a Linux host; `store` with an empty `AccountStorePath` keeps everything in memory, which is how the tests run.
